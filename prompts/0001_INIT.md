# Codex Task: Build Cloudflare Worker Container Proxy API for Codex Cloud
**Worker Name:** `codex-proxy-api`

---

## Objective
Create a Cloudflare Worker + container-based API proxy that connects Codex Cloud to GitHub and the Codex TypeScript SDK.  
This Worker should:
- Act as a **Codex Proxy** that allows code generation, repo management, and infrastructure scaffolding.
- Host a **React frontend** (served from `ASSETS`) for interacting with Codex Cloud visually.
- Dynamically sync **MCP servers** defined in `.mcp.json`.
- Default to **Workers runtime** (no Pages) and enforce Codex Cloud-only generation via the **Codex CLI binding**.

---

## Core Requirements

### 1. Base Architecture
- Worker runtime: **Cloudflare Workers (TypeScript)**.
- Container runtime: optional sidecar for gh CLI operations (list/create repos).
- Frontend: **React + Vite**, bundled to `/worker/public`, served via `ASSETS` binding.
- Framework: **Hono** (for routing and OpenAPI generation).
- Codex integration: **`packages/codex-typescript-sdk` + Codex CLI binding** (no external LLMs).
- Infra guidance: **cloudflare-docs MCP server** (and any others listed in `.mcp.json`).

---

### 2. `.mcp.json` Synchronization
This Worker must **read, parse, and sync** the `.mcp.json` configuration from the repository root:
```json
{
  "mcpServers": {
    "cloudflare-docs": {
      "type": "http",
      "url": "https://docs.mcp.cloudflare.com/mcp"
    },
    "exa": {
      "type": "http",
      "url": "https://mcp.exa.ai/mcp",
      "headers": {
        "Remove-Me": "Disable web_search_exa tool if you're just coding. To 100% call exa-code, say 'use exa-code'."
      }
    }
  }
}

Behavior:
	•	On Worker startup, load .mcp.json and register all defined MCP endpoints.
	•	Cache MCP registry in /.codex/mcp_registry.json.
	•	If .mcp.json changes (detected by hash or commit diff), trigger a Codex MCP refresh cycle:
	•	Rebuild internal registry.
	•	Update AGENTS.md to reflect new/removed MCPs.
	•	MCP entries (e.g., cloudflare-docs, exa) must be used for context-aware scaffolding:
	•	cloudflare-docs → Cloudflare infra guidance.
	•	exa → code generation augmentation (only if explicitly requested via "use exa-code").

3. Backend Endpoints (Hono)

Method	Path	Purpose
GET	/health	Returns basic status { ok: true, ts, version }
GET	/openapi.json, /openapi.yaml	Serve dynamically generated OpenAPI spec
GET	/gh/repos	List available repos (prefer gh CLI, fallback to GitHub API)
POST	/gh/repos	Create new repo via gh CLI or GitHub REST
POST	/codex/generate	Accept { repo, infra, prompts }, run Codex Cloud codegen
GET	/status/:jobId	Stream codegen progress/status

Infra Flags

When invoking /codex/generate, body includes:

{
  "repo": "string",
  "infra": {
    "durableObjects": true,
    "agentsSdk": false,
    "actorFramework": true,
    "workflows": false,
    "queues": false,
    "r2": true,
    "d1": false,
    "kv": true,
    "containers": false
  },
  "prompts": ["string"]
}

Each flag scaffolds associated Cloudflare bindings, stubs, and examples automatically.

9. Synchronization Logic (mcp.ts)
	•	Read .mcp.json from repo root.
	•	Compare with cached hash in /.codex/mcp_registry.json.
	•	If different → rebuild registry, call Codex CLI binding to update MCP context.
	•	Write changes to AGENTS.md under ## Connected MCP Servers.
	•	Expose endpoint /mcp/refresh for manual sync triggers.
